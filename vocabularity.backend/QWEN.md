## О проекте

- Vocabularity это мой pet проект для изучения английского языка.
- Его суть анализировать англоязычный контент и извлекать лексику для изучения.
- Этот проект отвечает за backend, его основная задача хранить новые слова для изучения в БД.

## Структура проекта

- migrations - содержит миграции написанные вручную. Миграции применяются с помощью go инструмента goose.
- scripts - инструменты powershell, которые я использую для вызова в vscode через tasks.json. Тут есть команда для сборки migrator.exe
- models - слой данных. dto - содержит выходные и входные модели, domain - содержит доменные модели, entities - содержит модели базы данных
- interactors - содержит интеракторы. В контексте текущего проекта interactor - это класс с методом execute, который выполняет use case
- repositories - репозитории, которые вызываются интеракторами для операций с БД
- test - содержит интеграционные тесты

## Важно

- Миграции должны применяться через migrator.exe. Для сборки migrator.exe нужно использовать powershell dcript build_migrator.ps1
- Интеракторы взаимодействуют исключительно с репозиториями, они не могут образатьс к БД напрямую
- Репозитории реализуют все необходимые CRUD операции. Принимают и отдают только доменные модели, а не entity
- Каждый use case это отдельный интерактор
- endpoint-ы должны соответствовать REST. Не иметь глаголов в названии и тд.
- endpoint-ы находятся в main.py и вызывают интеракторы. Для каждого Endpoint-а должнен быть описан входной и выходной dto
- Доменные модели и Entity это разное. Доменная модель не может содержать id и другие данные, которые нужны только базе
- Преобразование между слоями реализовано в самих моделях через метод to_слой. Например: to_entity, to_domain ...
